# Stock Copilot Phase B 深度调研报告

> 调研日期：2026-05-24
> 调研目标：解决两个核心问题
> 1. 信息应如何挖掘，才能对炒股决策有真实价值？
> 2. 信息/洞见在页面及交互方式应该如何设计？

---

## 一、业界信息挖掘方案调研

### 1.1 传统量化平台的信息挖掘

#### 聚宽 (JoinQuant) / 米筐 (RiceQuant)
- **核心方法**：因子挖掘 + 回测验证
- **有效因子**：
  - 动量因子（20 日/60 日收益率）
  - 波动率因子（历史波动率、ATR）
  - 估值因子（PE/PB/PS 分位数）
  - 资金流因子（主力净流入、北向资金）
  - 技术指标（MACD、RSI、布林带）
- **关键洞察**：单一因子无效，因子组合 + 动态权重才有效

#### 同花顺 iFinD / Wind
- **核心方法**：多维度数据聚合 + 事件驱动
- **高价值信息**：
  - 龙虎榜机构买卖（机构专用席位）
  - 大宗交易折价/溢价
  - 股东增减持公告
  - 研报评级变化（上调/下调）
  - 行业景气度指标

### 1.2 AI 驱动的新型方案

#### TradingAgents-AShare (学术)
- **核心方法**：多 Agent 分工 + 辩论机制
- **Agent 角色**：
  - Technical Analyst（技术面）
  - Fundamental Analyst（基本面）
  - Sentiment Analyst（情绪面）
  - Risk Manager（风险控制）
- **关键创新**：不是让 LLM 预测涨跌，而是让 LLM 提取结构化信息

#### FinAgent (学术)
- **核心方法**：多模态信息融合
- **信息源**：
  - 新闻标题情感分析
  - 财报电话会议文本
  - 社交媒体情绪
  - 技术指标
- **关键发现**：LLM 直接预测准确率约 52-55%，但信息提取准确率可达 85%+

### 1.3 高价值信息挖掘框架

基于调研，对 A 股个人投资者最有价值的信息分层：

#### Layer 1: 确定性信息（高置信度）
| 信息类型 | 获取方式 | 价值 |
|---------|---------|------|
| 价格/成交量 | 行情 API | 基础 |
| 均线排列 | 计算 | 趋势判断 |
| PE/PB 分位数 | 估值 API | 估值高低 |
| 主力净流入 | 资金流 API | 短期动能 |
| 龙虎榜机构买卖 | 东财 datacenter | 机构态度 |

#### Layer 2: 半结构化信息（中置信度）
| 信息类型 | 获取方式 | 价值 |
|---------|---------|------|
| 公告关键词提取 | NLP 摘要 | 事件驱动 |
| 研报评级变化 | 爬虫/API | 机构预期 |
| 股东增减持 | 公告解析 | 内部人信号 |
| 行业政策新闻 | 新闻情感分析 | 板块轮动 |

#### Layer 3: 软信息（低置信度，需验证）
| 信息类型 | 获取方式 | 价值 |
|---------|---------|------|
| 社交媒体情绪 | 雪球/东方财富股吧 | 散户情绪 |
| LLM 综合研判 | Prompt 工程 | 信息整合 |
| 技术形态识别 | 模式识别 | 支撑压力位 |

### 1.4 关键结论：信息挖掘的"三不"原则

1. **不预测**：LLM 不应该预测涨跌，而是提取结构化信息
2. **不编造**：所有数据必须有来源，无数据时明确标注"不可用"
3. **不替代**：AI 是辅助工具，最终决策权在人

## 二、业界交互方式调研

### 2.1 传统金融终端

#### Bloomberg Terminal
- **交互特点**：信息密度极高，快捷键驱动
- **借鉴点**：信息分层展示，关键数据突出显示
- **不适用**：学习成本太高，不适合个人投资者

#### 同花顺/东方财富
- **交互特点**：图表为主，数据表格为辅
- **借鉴点**：K 线图 + 技术指标叠加，资金流向可视化
- **不适用**：信息过载，缺乏 AI 总结

### 2.2 新型 AI 投研产品

#### 且慢 AI 小顾
- **交互特点**：对话式 + 卡片式报告
- **借鉴点**：
  - 每日简报卡片（3-5 个关键点）
  - 风险提示醒目
  - 语言通俗易懂
- **核心优势**：降低认知负荷，聚焦关键信息

#### TradingView
- **交互特点**：图表交互 + 社区观点
- **借鉴点**：
  - 技术指标可切换
  - 观点可点赞/评论
  - 时间轴对比
- **不适用**：社区噪音大

### 2.3 最佳实践总结

#### 信息展示层级（金字塔原则）
```
第一层：结论先行（1 句话）
  ↓
第二层：核心依据（3-5 个关键点）
  ↓
第三层：详细数据（可展开）
```

#### 交互设计原则
1. **3 秒原则**：用户 3 秒内看到核心结论
2. **渐进式披露**：先结论，后依据，再详情
3. **信号可视化**：用颜色/形状/大小直观表达
4. **可解释性**：每个结论都有明确依据
5. **风险提示**：始终可见，不隐藏

#### 新增数据源

| 股东增减持 | 内部人信号 | P1 |
| 行业政策新闻 | 板块轮动 | P2 |

#### LLM Prompt 重构
从"预测涨跌"改为"信息提取"：
```
你是一个专业的 A 股信息提取助手。基于以下数据，提取关键信息：

【数据输入】
- 技术指标：{technical_data}
- 资金流向：{capital_data}
- 公告摘要：{announcements}
- 龙虎榜：{dragon_tiger}

【输出要求】
1. 关键事件（1-3 个）
2. 潜在影响（正面/负面/中性）
3. 影响时间范围（短期/中期/长期）
4. 置信度（0-100%）
5. 风险提示

【约束】
- 仅基于提供的数据
- 不预测涨跌
- 无数据时标注"不可用"
```

## 五、关键设计决策

### 5.1 为什么不直接预测涨跌？
- 学术研究表明 LLM 预测准确率仅 52-55%
- 但信息提取准确率可达 85%+
- 预测容易误导，信息提取辅助决策

### 5.2 为什么采用金字塔结构？
- 降低认知负荷
- 聚焦关键信息
- 支持渐进式探索

### 5.3 为什么强调可解释性？
- 用户需要理解为什么给出某个信号
- 可解释的信号更可信
- 便于用户验证和调整
